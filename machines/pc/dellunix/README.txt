Dell UNIX System V Release 4.0 Issue 2.2 (1992) for x86 on QEMU's PC (Pentium, 64 MB, i440FX, S3 Trio64V+ with 4 MB, WD8003E Ethernet)

Run ./run.sh (macOS 26+ arm64, Linux x86_64/aarch64 with glibc 2.34+ and X11/XWayland) or run.cmd (Windows 10+ x64).
Dell UNIX boots to an X11 login box (xdm) in about 10 seconds. Log in as root, no password: type root, then press Enter at Password:. telnet localhost 22023 works too.
X11: after the login you get the Motif window manager (mwm), an xterm and a clock; click a window to type in it. Hold the right mouse button on the background for Dell's menu: New Window (an xterm), Applications, Shutdown (Powerdown or Reboot) and Quit/Logout. Ctrl-Alt-Backspace restarts X.
X runs 1280x1024 with 256 colours. The X server is Dell's own (X386 1.2, /usr/X5/bin/Xmach.s3), rebuilt from Dell's source code with a new driver for the S3 Trio64: the S3 engine does the copies and fills, and the pointer is the S3 hardware cursor. Other sizes: as root, /usr/local/bin/xserver 1600x1200 (or 640x480, 800x600, 1024x768, 1152x864, 2048x1536), then Shutdown > Reboot in Dell's menu. To boot to the text console instead: rm /etc/rc2.d/S99xdm and reboot; startx then starts X.
Installed: Dell UNIX with all 39 packages of Dell's tape: X11R5 (mwm, olwm, twm, xterm, xman, xv, xfig, tgif and many more in /usr/X5/bin), FrameMaker 3.0X, GNU emacs, gcc 2.1, gdb, make, perl 4, TeX and LaTeX with xdvi, tcsh 6.01, less, top, elm, rn and nn, kermit and the manual pages.
FrameMaker: type /usr/frame/bin/maker in an xterm (or imaker or viewer). It is licensed for the displays :0, unix:0, amnesia:0 and localhost:0, in /usr/frame/.fminit2.0/framepasswd. /usr/frame/bin/demomaker runs Frame's demo mode, with its 21-page tour.
Extra apps in /usr/local/bin (not in the PATH): bash 1.14.7, gzip, wget 1.5.3, ncftp, NCSA Mosaic 2.5 (mosaic) and 1.2 (xmosaic), and the JPEG tools.
Ported in 2026, also in /usr/local/bin: archaic, a web browser for WRP (https://github.com/tenox7/archaic), which looks for WRP at 192.168.1.10:8080, port 8080 on this computer; tenoxvnc, a VNC viewer; sng, a system and network grapher; simcity, DUX SimCity 2.17 for X11, its files in /usr/SimCity, with sim built from https://github.com/tenox7/micropolis-legacy. Start them in an xterm, such as /usr/local/bin/simcity &.
Web: /usr/local/bin/mosaic & in the xterm. Mosaic 2.5 (1994) speaks plain HTTP only, sends no Host: header and saves pages that name a charset as files, so few sites work today. http://textfiles.com/ does, but Mosaic crashes on about half of its loads ("Congratulations, you have found a bug"): start it again.
Network: a Western Digital WD8003E ISA card, set as Dell's driver wants it (I/O 0x280, IRQ 5, memory 0xD0000). QEMU user mode NAT; Dell UNIX keeps its address 192.168.1.111 (host name amnesia) with gateway and DNS 192.168.1.1, and this computer is 192.168.1.10. telnet localhost 22023 reaches Dell UNIX; the port listens on this computer only.
The clock is the host's local time; Dell UNIX shows 2026 fine.
Mouse: a Microsoft serial mouse on COM1. QEMU grabs it when you click in the window; Ctrl-Alt-G lets it go. When X starts, the pointer jumps by about 400 pixels: move the mouse.
QEMU halts the CPU while Dell UNIX is idle, so an idle VM uses about 1% of a host core.
Shut down with Shutdown > Powerdown in Dell's menu, or shutdown -y -g0 -i0 as root, and wait for "Press any key to reboot" before quitting QEMU. To restart, use Shutdown > Reboot or shutdown -y -g0 -i6, not reboot: that is BSD's reboot, which skips the shutdown scripts.
macOS: if the binary is blocked, run xattr -cr . in this folder.

AI agents (macOS, Linux): in this folder, claude mcp add lemu -s user -- "$PWD/bin/macos-arm64/qemu-system-i386" -mcp-bridge (on Linux bin/linux-x86_64 or bin/linux-aarch64) lets an agent such as Claude Code see the screen and use the keyboard, mouse and serial ports of the running VM. See MCP.md in the QEMU source.
QEMU source: https://github.com/tenox7/lemu branch master (GPLv2, see bin/COPYING). qemu-system-i386 --version names the commit. LEMU added the WD8003E card and faster S3 engine copies and fills for this kit. fw/s3t64vp.bin is S3's video BIOS for the Trio64V+.
